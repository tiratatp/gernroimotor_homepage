# เกินร้อยมอเตอร์ — เว็บไซต์หน้าร้าน (หน้าเดียว)

เว็บไซต์หน้าร้านเกินร้อยมอเตอร์ 1 หน้า ภาษาไทย เอาไว้ใช้กับ Google Maps และโฆษณา
โฮสต์ฟรีบน GitHub Pages พร้อมใช้โดเมนเฉพาะของร้านได้

**กฎทอง: แก้ทุกอย่างผ่านเว็บไซต์ GitHub (github.com) ไม่ต้องติดตั้งโปรแกรมอะไรเลย**
Golden rule: edit everything through the GitHub website — no software to install.

---

เว็บนี้มีไฟล์สำคัญ 2 ไฟล์ที่คุณต้องแก้:
- **`variables.txt`** — ข้อมูลร้านที่ใช้ซ้ำหลายที่ (ชื่อร้าน เบอร์โทร ที่อยู่ LINE Facebook TikTok โดเมน)
- **`template.html`** — ข้อความทั่วไปและรูปภาพบนหน้าเว็บ

ระบบ GitHub จะสร้างไฟล์ `index.html` (หน้าเว็บจริง), `robots.txt` และ `sitemap.xml` สำหรับ Google จากไฟล์ที่คุณดูแลให้อัตโนมัติทุกครั้งที่บันทึก

### แก้ไขที่ 1: เปลี่ยนข้อมูลร้าน (ชื่อร้าน/เบอร์โทร/ที่อยู่/LINE/Facebook/TikTok/โดเมน)

1. เปิดไฟล์ `variables.txt` บน GitHub (คลิกชื่อไฟล์)
2. คลิกปุ่มดินสอ (Edit) มุมขวาบน
3. แก้เฉพาะ **ข้อความทางขวาของเครื่องหมาย `=`** เท่านั้น
4. กด **Commit changes**

> **คำเตือนสำคัญ: แก้เฉพาะทางขวาของเครื่องหมาย `=` เท่านั้น ห้ามแตะชื่อทางซ้าย**
> ถ้าลบหรือเปลี่ยนชื่อทางซ้าย หรือพิมพ์รูปแบบข้อมูลไม่ถูกต้อง ระบบจะไม่สร้างเว็บให้

**ตัวอย่าง:**
```
ก่อนแก้:  PHONE_DISPLAY = 02-000-0000
หลังแก้:  PHONE_DISPLAY = 089-123-4567
```

**ตารางตัวแปรทั้งหมด (12 ตัว) และ รูปแบบที่ระบบรองรับ:**

| ชื่อตัวแปร | คำอธิบาย | รูปแบบที่ต้องใช้ (ถ้าใส่ผิดระบบจะแจ้งเตือน) |
|-----------|----------|-----------------------------------------|
| `SHOP_NAME` | ชื่อร้าน (แสดงบนหน้าเว็บ แท็บเบราว์เซอร์ และข้อมูล Google) | ข้อความทั่วไป |
| `PHONE_DISPLAY` | เบอร์โทรแบบมีขีด สำหรับแสดงบนหน้าเว็บ | รูปแบบ `0XX-XXX-XXXX` (เช่น 089-123-4567) |
| `PHONE_TEL` | เบอร์โทรสำหรับปุ่มกดโทร | ตัวเลข 10 หลักขึ้นต้นด้วย 0 ไม่มีขีด (เช่น 0891234567) |
| `PHONE_TEL_INTL` | เบอร์โทรแบบสากล สำหรับข้อมูล Google (JSON-LD) เท่านั้น | ขึ้นต้นด้วย `+66` ตามด้วยตัวเลข 9 หลัก (เช่น +66891234567) |
| `PHONE_BACKUP_DISPLAY` | เบอร์โทรสำรองแบบมีขีด สำหรับแสดงบนหน้าเว็บ | รูปแบบ `0XX-XXX-XXXX` (เช่น 094-595-9624) |
| `PHONE_BACKUP_TEL` | เบอร์โทรสำรองแบบตัวเลขล้วน สำหรับปุ่มกดโทร | ตัวเลข 10 หลักขึ้นต้นด้วย 0 ไม่มีขีด (เช่น 0945959624) |
| `ADDRESS` | ที่อยู่: เลขที่ ถนน แขวง เขต (ไม่ต้องใส่ กรุงเทพฯ และรหัสไปรษณีย์) | ข้อความทั่วไป |
| `POSTAL_CODE` | รหัสไปรษณีย์ | ตัวเลข 5 หลักเท่านั้น (เช่น 10230) |
| `LINE_ID` | LINE ID ของร้าน | ตัวอักษรภาษาอังกฤษ, ตัวเลข, `.`, `_`, `-` เท่านั้น (ห้ามใส่ `@`, ช่องว่าง, `/` หรือ URL) |
| `FACEBOOK_PAGE` | ชื่อเพจ Facebook (ส่วนท้ายของลิงก์) | ตัวอักษรภาษาอังกฤษ, ตัวเลข, `.`, `_`, `-` เท่านั้น (ห้ามใส่ `@`, ช่องว่าง, `/` หรือ URL เช่น facebook.com/ชื่อเพจ ให้ใส่เฉพาะ `ชื่อเพจ`) |
| `TIKTOK_USER` | ชื่อบัญชี TikTok | ตัวอักษรภาษาอังกฤษ, ตัวเลข, `.`, `_`, `-` เท่านั้น (ห้ามใส่ `@`, ช่องว่าง, `/` หรือ URL เช่น `100motor.bkk`) |
| `SITE_URL` | โดเมนจริงของเว็บ | ต้องเป็น `https://` มีชื่อโดเมน ไม่มี query string/fragment และต้องลงท้ายด้วย `/` (เช่น `https://www.yourshop.com/`) |

### แก้ไขที่ 2: เปลี่ยนข้อความทั่วไปหรือรูปภาพ

1. เปิดไฟล์ `template.html` บน GitHub
2. คลิกปุ่มดินสอ (Edit)
3. กด `Ctrl+F` (หรือ `Cmd+F`) แล้วค้นหาคำว่า **`EDIT ME`** หรือ **`แก้ไขตรงนี้`**
4. แก้ข้อความที่ต้องการ
5. กด **Commit changes**

> **ข้อควรระวังสำคัญสำหรับการแก้ไขคำถามคำตอบ (FAQ):**
> คำถามและคำตอบที่แสดงบนหน้าเว็บ (ในส่วน FAQ) ต้องมีข้อความตรงกับข้อมูลโครงสร้างสำหรับ Google (FAQPage JSON-LD) ที่อยู่ท้ายไฟล์ `template.html`
> หากแก้คำถามหรือคำตอบที่หน้าเว็บแล้ว อย่าลืมแก้ในชุดข้อมูล JSON-LD ท้ายไฟล์ให้ตรงกันด้วย ไม่งั้นระบบตรวจสอบความปลอดภัยจะไม่อนุญาตให้เผยแพร่เว็บ

**วิธีเปลี่ยนรูปภาพ:**

1. เตรียมรูปภาพของร้าน (ถ่ายด้วยมือถือก็ได้) — ต้องเป็นไฟล์ **JPG หรือ PNG เท่านั้น** และใหญ่ไม่เกิน **5 MB** ต่อรูป
   (ไม่ต้องย่อรูปเอง — ระบบจะย่อรูปและแปลงเป็น WebP เล็กลงให้อัตโนมัติตอนเผยแพร่เว็บ)
2. บน GitHub คลิก **Add file → Upload files**
3. สร้างโฟลเดอร์ `images` โดยพิมพ์ `images/` ในช่องชื่อไฟล์ แล้วอัปโหลดรูปเข้าไป
   (เช่น อัปโหลดไฟล์ชื่อ `shop-front.jpg` → จะได้พาธ `images/shop-front.jpg`)
4. เปิด `template.html` แล้วค้นหาคำว่า **`SWAP IMAGE`** หรือ **`เปลี่ยนรูปตรงนี้`**
5. เปลี่ยน URL จาก `https://placehold.co/...` เป็น `images/ชื่อรูปของคุณ.jpg`
6. กด **Commit changes**

> รูปในเว็บตอนนี้เป็นรูปจริงของร้านแล้ว (images/logo.jpg และ images/shop-front.jpg)
> ถ้าอยากเปลี่ยนหรือเพิ่มรูป ทำตามขั้นตอนด้านบนได้เลย

### แก้ไขที่ 3: เพิ่มการ์ดบริการ รูปในแกลเลอรี หรือยี่ห้อ/รุ่นรถ

1. ใน `template.html` ค้นหาคำว่า **`COPY FROM HERE`** หรือ **`คัดลอกตั้งแต่ตรงนี้`**
2. คัดลอกทุกอย่างตั้งแต่บรรทัด `COPY FROM HERE` จนถึงบรรทัด `TO HERE` / `ถึงตรงนี้`
3. วางต่อจากบล็อกเดิม (ในตำแหน่งเดียวกัน)
4. แก้ข้อความในบล็อกใหม่
5. กด **Commit changes**

> ใช้วิธีนี้เพื่อ: เพิ่มการ์ดบริการใหม่, เพิ่มรูปในแกลเลอรี,
> เพิ่มย่อหน้าเกี่ยวกับเรา, เพิ่มช่องทางติดต่อ, เพิ่มยี่ห้อรถและรุ่นรถ (คัดลอก `<li class="chip">` ในส่วนยี่ห้อและรุ่นรถ)

## ตอนบันทึกแล้วเกิดอะไรขึ้น

ทุกครั้งที่กด **Commit changes** ระบบ GitHub Actions จะทำงานเป็นขั้นตอนเพื่อความปลอดภัยสูงสุด:

1. **Run safety tests** — ตรวจสอบความถูกต้องของข้อมูลและโครงสร้างเว็บ (เช่น เช็คว่า FAQ บนหน้าเว็บตรงกับข้อมูล Google หรือไม่)
2. **Build website from template** — รวมไฟล์ `variables.txt` + `template.html` เป็น `index.html` พร้อมสร้าง `robots.txt` และ `sitemap.xml`
3. **Validate & Optimize** — ตรวจสอบโครงสร้าง HTML, ตรวจสอบขนาด/ประเภทรูปภาพ แล้วทำการย่อรูปภาพและไฟล์ HTML ให้โหลดเร็วที่สุด
4. **Publish** — เผยแพร่เฉพาะไฟล์ที่ย่อและตรวจผ่านแล้วขึ้นหน้าเว็บจริง

- **เครื่องหมายเช็คเขียว (✓)** = ทุกขั้นตอนผ่านเรียบร้อย เว็บอัปเดตภายใน 1-2 นาที
- **เครื่องหมาย X สีแดง** = ตรวจพบข้อผิดพลาด เว็บเดิมยังออนไลน์อยู่ปกติ ไม่มีอะไรพัง ระบบจะไม่นำไฟล์ที่เสียขึ้นเว็บจริง

## ถ้าเว็บไม่อัปเดต / มีเครื่องหมาย X สีแดง

ถ้าแก้ไฟล์แล้วเว็บไม่อัปเดต หรือเห็นเครื่องหมาย X สีแดงที่แท็บ Actions แปลว่าการแก้ไขทำให้ไฟล์เสีย:

1. เข้า GitHub → คลิกแท็บ **Actions** (ด้านบนของหน้า repo)
2. คลิกการรันที่มีเครื่องหมาย X สีแดง (failed run)
3. ดูว่า step ไหนที่ fail แล้วแก้ตาม:

**ถ้า "Run safety tests" fail:**
- สาเหตุที่พบบ่อยที่สุด: ข้อความคำถามหรือคำตอบในส่วน FAQ บนหน้าเว็บ ไม่ตรงกับข้อมูล FAQPage JSON-LD สำหรับ Google ที่อยู่ท้ายไฟล์ `template.html`
- แก้: ปรับข้อความคำถามและคำตอบทั้งสองจุดใน `template.html` ให้เป็นข้อความเดียวกัน

**ถ้า "Build website from template" fail:**
- ไฟล์ `variables.txt` หรือ `template.html` มีปัญหา — log จะบอกเป็นภาษาไทยว่าผิดตรงไหน
- เช่น: ขาดเครื่องหมาย `=`, ค่าว่างเปล่า, ชื่อตัวแปรซ้ำกัน, พิมพ์รูปแบบข้อมูลผิด (เช่น เบอร์โทรผิดหลัก, ใส่ URL ใน LINE ID, SITE_URL ไม่ใช้ https หรือไม่ลงท้ายด้วย `/`), หรือใส่ตัวแปร placeholder `{{...}}` ผิดรูปแบบ
- แก้: กลับไปแก้ไข `variables.txt` หรือ `template.html` ให้ถูกต้องตามรูปแบบที่กำหนด

**ถ้า "Validate HTML structure" fail:**
- แท็กใน `template.html` ขาดหรือเสีย — log จะบอกเลขบรรทัดที่มีปัญหา
- แก้ที่ปลอดภัยที่สุด: ยกเลิกการแก้ไขครั้งล่าสุด (undo / revert)

**ถ้า step ที่ขึ้นต้นด้วย "Check ..." fail:**
- อาจลบคำว่า `EDIT ME` หรือบล็อก `<style>` หรือแท็กปิดไปโดยไม่ได้ตั้งใจ
- แก้: คืนค่าส่วนที่ลบไปกลับมา

**ถ้า "Check image files" fail:**
- รูปที่อัปโหลดไม่ใช่ JPG/PNG (เช่นไฟล์ HEIC จาก iPhone) หรือไฟล์ใหญ่เกิน 5 MB
- แก้: เปิดโฟลเดอร์ `images` บน GitHub → ลบไฟล์ที่มีปัญหาออก → แปลงรูปเป็น JPG หรือย่อให้เล็กลง → อัปโหลดใหม่

**ทางออกสุดท้าย:** ถ้าแก้ไม่ได้ ให้เอา repo ทั้งหมดพร้อม README นี้ ให้นักพัฒนาหรือ AI agent ช่วยแก้

## ไฟล์ที่เผยแพร่บนเว็บจริง และไฟล์ที่ห้ามแตะ

เมื่อระบบตรวจผ่านและเผยแพร่เว็บ ระบบจะนำเฉพาะไฟล์เว็บสำหรับแสดงผลจริงขึ้นโฮสติ้งเท่านั้น ได้แก่:
- `index.html` (สร้างให้อัตโนมัติ)
- `robots.txt` และ `sitemap.xml` (สร้างให้อัตโนมัติ)
- โฟลเดอร์ `images/` (ย่อขนาดและแปลงไฟล์ให้อัตโนมัติ)
- `CNAME` (ถ้ามีการตั้งค่าโดเมนเฉพาะ)

ไฟล์ต้นฉบับ เช่น `template.html`, `variables.txt`, `README.md`, `build.py` และไฟล์ทดสอบต่างๆ จะไม่ถูกนำขึ้นเว็บจริง

**ไฟล์ที่ห้ามแตะ (อันตราย):**
- **`index.html`** — ไฟล์นี้ถูกสร้างอัตโนมัติจาก `template.html` + `variables.txt` แก้แล้วจะถูกเขียนทับทุกครั้ง
- **`build.py`** — โปรแกรมสร้างเว็บ ห้ามแก้เด็ดขาด
- **`.github/`** — ระบบตรวจสอบและเผยแพร่อัตโนมัติ ห้ามแก้
- **`.htmlvalidate.json`** — ไฟล์ตั้งค่าการตรวจสอบ HTML ห้ามแก้

## Deployment (step-by-step)

### First-time setup (3 bullets)

1. Push all files to the `main` branch of a GitHub repository.
2. Go to **Settings → Pages → Source** and select **GitHub Actions** (NOT "Deploy from branch").
3. The workflow runs automatically on every push to `main`; after the first green check, the site is live at `https://<username>.github.io/<repo>/`.

### Custom domain (โดเมนของตัวเอง)

1. **ตั้งค่า SITE_URL** ใน `variables.txt` เป็นโดเมนจริงของร้าน (เช่น `https://www.yourshop.com/`)
2. **สร้างไฟล์ CNAME** ใน repo ชื่อไฟล์ `CNAME` (ไม่มีนามสกุล) บรรจุโดเมนเดียวบรรทัดเดียว:
   ```
   www.yourshop.com
   ```
   > ห้ามใส่โดเมนจำลอง — ต้องเป็นโดเมนจริง ไม่งั้นลิงก์ github.io เริ่มต้นจะพัง
3. **ตั้งค่า DNS** ที่ผู้ให้บริการโดเมน:

   **สำหรับโดเมนหลัก** (เช่น `yourshop.com`) ให้เพิ่ม A records ชี้ไปที่ IP ของ GitHub Pages:

   | Type | Host | Value |
   |------|------|-------|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |

   **สำหรับ www** (เช่น `www.yourshop.com`) ให้เพิ่ม CNAME record:

   | Type | Host | Value |
   |------|------|-------|
   | CNAME | `www` | `<username>.github.io` |

   > แทนที่ `<username>` ด้วยชื่อผู้ใช้/องค์กร GitHub ของคุณ

4. **เปิด Enforce HTTPS**: ไปที่ **Settings → Pages** → ใส่โดเมนในช่อง Custom domain → กด **Save** → รอ DNS แพร่กระจาย (ไม่กี่นาทีถึงหลายชั่วโมง) → ติ๊ก **Enforce HTTPS**

> การเปลี่ยนแปลง DNS อาจใช้เวลาตั้งแต่ไม่กี่นาทีถึงหลายชั่วโมง

## Pre-publish checklist (ตรวจสอบก่อนเปิดใช้งาน)

ก่อนเปิดเว็บจริง ให้ทำตามนี้:
